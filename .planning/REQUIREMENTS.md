# Requirements: gsd-graphify-workshop

**Defined:** 2026-10-05
**Milestone:** v1.0 Экспорт отчёта в Markdown
**Core Value:** Человек открывает снимок и видит, как на уже инициализированном канбане записан первый майлстоун: цель, требования и фазы, без исполненного кода.

## User Stories

- Как участник доски, я получаю файл Markdown с текущими задачами и вижу те же три колонки, что на доске.
- Как участник, я читаю заголовок и описание задачи как текст, даже если в них есть знаки Markdown.
- Как слушатель воркшопа, я вижу, что поведение отчёта без единой задачи ещё не выбрано, и следующий шаг — обсуждение фазы 1.

## Acceptance Criteria

- Файл начинается с заголовка Task Board, затем секции To Do, In Progress, Done.
- В секции задачи идут по возрастанию `position`. Описание попадает в файл только когда оно непустое.
- Секция колонки есть и тогда, когда в этой колонке нет карточек, а на доске задачи есть.
- Символы разметки в `title` и `description` не открывают новый заголовок, список, ссылку или код.
- Одинаковый набор задач даёт одинаковый текст файла. В файл не входят `id`, `createdAt`, `updatedAt`.
- Для доски без задач нажатие Export markdown не скачивает файл и показывает баннер Nothing to export.
- Чекбоксы требований и планов пустые.

## Definition of Done

- Пункты v1 ниже привязаны ровно к одной фазе роадмапа.
- Чекбоксы v1 и фаз пустые, статусы трассировки — Pending.
- `STATE.md` показывает прогресс 0 и следующий шаг `/gsd-discuss-phase 1`, который в этом снимке не запускался.
- У каждой фазы один план в `.planning/phases/`. Чекбоксы планов пустые.
- Код в `apps/` и `packages/` совпадает со снимком `02-gsd-init`.

## v1 Requirements

Требования этого майлстоуна. Каждое попадёт ровно в одну фазу. Чекбокс остаётся пустым: запись требования не означает, что фаза исполнена.

### Состав отчёта

- [x] **RPT-01**: Участник получает файл, в котором заголовок Task Board и секции To Do, In Progress, Done стоят в этом порядке.
- [x] **RPT-02**: Участник видит в секции текущие задачи этой колонки по возрастанию `position`; непустое `description` входит в файл, пустое — нет.
- [x] **RPT-03**: Участник видит заголовок секции и тогда, когда в колонке нет карточек, а на доске есть другие задачи.

### Безопасный текст

- [ ] **RPT-04**: Участник читает `title` и `description` как текст: знаки Markdown не становятся заголовком, списком, ссылкой или кодом.
- [ ] **RPT-05**: Участник получает один и тот же текст файла для одного и того же набора задач. `id`, `createdAt` и `updatedAt` в файл не входят.

### Пустой отчёт

- [ ] **RPT-06**: Для доски без единой задачи нажатие Export markdown не скачивает файл и показывает баннер Nothing to export.

## v2 Requirements

Другие снимки. В текущий роадмап не входят.

### Следующие уроки

- **DISC-01**: Слушатель проходит `/gsd-discuss-phase 1` и видит записанный выбор для пустого отчёта.
- **PLAN-01**: Слушатель проходит `/gsd-plan-phase` и видит каталог `.planning/phases/` с планами.
- **EXEC-01**: Слушатель исполняет фазу, и в снимке появляется экспорт, а не только документы майлстоуна.
- **GRAPH-01**: Слушатель смотрит, как граф на ветке `01-graphify` связан с новым кодом, в отдельном снимке.

## Out of Scope

| Feature | Reason |
|---------|--------|
| Файл с пояснением вместо ошибки на пустой доске | Для демо выбран баннер Nothing to export |
| Запись отчёта на диск сервера | Файл только скачивается в браузере |
| Правка `apps/`, `packages/`, `docs/`, `docs/_ai/` в этом снимке | Планы описывают правки, исполнение — следующий шаг |
| Автотесты, Docker, CI, вход, OpenAPI | Их нет в приложении, майлстоун их не добавляет |
| Редактирование заголовка на доске, роли | Не входят в экспорт |
| Фильтры, PDF, отправка отчёта | Шум для учебного примера |
| Закрытые чекбоксы | Закрытый пункт выглядит как прошедшее исполнение |
| Перезапись `02-gsd-init` | Инициализация остаётся отдельной стадией |
